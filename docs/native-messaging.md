# Grid Analyzer Yerel Hesap Motoru · v6.1.4

Protocol version: **1.0**. Host name: `com.ytbs.powerfactory.solver`. The Python package pins pandapower **3.5.5**. The installer creates a virtual environment, installs the package and registers the generated executable `ytbs-solver-host.exe` in `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.ytbs.powerfactory.solver`. It writes `com.ytbs.powerfactory.solver.json` with the current extension ID in `allowed_origins`; it does not create a `.cmd` launcher.

The application displays its current `chrome.runtime.id` and prepares this PowerShell command:

```powershell
.\native-host\python\scripts\install-windows.ps1 -ExtensionId <CURRENT_EXTENSION_ID>
```

Run it from the repository root, fully close and reopen Chrome, then use **Bağlantıyı test et**. The connection test sends `HELLO` and receives `HOST_STARTED`, `HELLO_ACK` and `CAPABILITIES`; it reports protocol, engine and engine version without sending a model. Remove the registration with `./native-host/python/scripts/uninstall-windows.ps1`.

On Windows, `node tools/native-host-smoke.mjs --extension-id=<CURRENT_EXTENSION_ID>` reads the Chrome HKCU/HKLM registration, validates the manifest, origin, executable and Python imports, and runs a direct framed `HELLO`. It prints `processStartMs`, `hostStartedMs`, `helloAckMs`, `helloResponseMs` and dependency versions. `node tests/e2e/native-health.mjs` builds the extension, temporarily registers its actual ID, tests Chrome Native Messaging and the UI health button without loading a DGS file, then restores the previous registration and manifest. The installed manifest is UTF-8 without a BOM.

Messages use Chrome's little endian 32-bit byte length frame and UTF-8 JSON. Every message has `protocolVersion`, `requestId` and `jobId`; the unsolicited `HOST_STARTED` frame has empty IDs. Commands: `HELLO`, `CREATE_MODEL`, `MODEL_CHUNK`, `MODEL_COMPLETE`, `PREFLIGHT`, `RUN_LOAD_FLOW`, `PING`, `CANCEL`. Responses: `HOST_STARTED`, `HELLO_ACK`, `CAPABILITIES`, `PROGRESS`, `DIAGNOSTICS`, `RESULT_SUMMARY`, `RESULT_CHUNK`, `PONG`, `ERROR`. The solver reports `SOLVING_AC` or `SOLVING_DC` immediately before calling pandapower. It reports real job phases and elapsed time; it does not manufacture iteration percentages. Model chunks are 128 KiB and result chunks are 192 KiB. Length, order, SHA-256, version and job correlation are checked. The host accepts no path, URL, shell or Python code commands.

Host failures are separated into unregistered host, extension-origin mismatch, start failure, disconnect, crash, protocol error, solver-reported error and timeout. An explicit pandapower import failure is reported as `PANDAPOWER_IMPORT_ERROR`. The health check also distinguishes a missing startup frame (`HOST_START_TIMEOUT`), missing HELLO acknowledgement (`HELLO_TIMEOUT`) and missing capabilities after acknowledgement (`CAPABILITIES_TIMEOUT`). Startup and HELLO allow 15 seconds each; capabilities after acknowledgement allow 30 seconds. Cold framed HELLO measurements on the development Windows machine ranged from 3.6–5.1 seconds directly and reached 6.2 seconds through Chrome, exceeding the previous 3-second whole-check limit. One health attempt after loading the 143 MB model exceeded 15 seconds at the acknowledged capability stage; a repeat completed in 2.2 seconds. The longer capability limit accommodates that observed cold-start variation. An unknown failure before connection is reported as a start failure, never as proof that the host is uninstalled. Chrome does not reveal whether a generic pre-start error came from the manifest path, executable or Python environment; the direct smoke checks these stages locally.

**Cancellation limitation:** `CANCEL` is handled between synchronous host commands. Once `pandapower.runpp` or `rundcpp` starts, the native host's command loop cannot read a cancellation message until the solve returns. This release has no cancel button and does not claim to interrupt an active solver process. The extension times out after five minutes and closes its native port.

Models and results remain local to the browser and native host. Browser Approx output is not relabeled as a pandapower result.
