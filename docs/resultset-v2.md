# ResultSet V2

`src/analysis/result-set.ts` defines typed bus, branch end, branch, transformer, generator, external-grid, loss and network-summary records. The host produces JSON `schemaVersion: "2.0"`; the extension checks the schema version, engine, model hash, result length, ordering and SHA-256 before showing it. Results retain `engineVersion`, `topologyMode`, `electricalScope`, convergence, validation, warnings and per-element unsupported reasons.

Units: voltage pu/kV, angle degrees, P MW, Q MVAr, apparent power MVA, current A, loading percent, losses MW/MVAr. Terminal names (`from/to`, `hv/lv`) are explicit. `null` denotes an uncomputed value, such as a disconnected bus. DC results contain P and angle; voltage magnitude, Q, current, loading and losses are `null` because the DC approximation does not solve them. `quality` is `CALCULATED`, `APPROXIMATE`, etc.; neither implies a measurement or PowerFactory validation.

`toLegacyRows` adapts a pandapower result to the existing map, SLD and analysis overlay. `fromLegacyRows` preserves the Browser Approx. data in V2, marked `TRANSMISSION_REDUCED` and `REDUCED`. IndexedDB stores the latest result under a model-hash and engine key. The comparison table aligns IDs and metrics for bus V/angle, line P/Q, transformer P/Q, generator Q and system losses. A user can load a `PowerFactory` engine ResultSet V2 JSON with the same model hash. This computes absolute and relative pandapower error. It does not automatically mark the model `VALIDATED` because provenance and acceptable tolerances must be checked separately. With no reference, error cells stay blank and a separate column displays the difference between engines.
