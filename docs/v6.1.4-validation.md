## Native host kök nedeni

HKCU Chrome NativeMessagingHosts kaydı, gösterdiği manifest, `com.ytbs.powerfactory.solver` adı, manifestin izin verdiği gerçek Extension ID ve `.venv/Scripts/ytbs-solver-host.exe` yolu doğrulandı. Python 3.12.10; pandapower 3.5.5; NumPy 2.4.6; SciPy 1.18.1 içe aktarılabiliyor. Direct framed HELLO ve gerçek Chrome HELLO, `CAPABILITIES` yanıtı aldı.

Eski `healthCheck` sınırı **3.000 ms** idi. Doğrudan soğuk başlangıçta CAPABILITIES **4.199 ms** sürdü; kurulum doğrulamasında gerçek Chrome yanıtı **6.160 ms**, UI health denetimi **5.418 ms** sürdü. Bu yüzden eski UI zaman aşımı, geçerli bağlantıyı yanlışlıkla başarısız gösteriyordu. Tam model yüklü bir tanı koşusunda HELLO_ACK alınmasına rağmen 15 saniyelik CAPABILITIES sınırı aşıldı (15.636 ms'de hata); sonraki tanı koşusu 2.196 ms'de tamamlandı. Yeni denetim host başlangıcı ve HELLO için **15.000 ms**, onaylanmış HELLO sonrası pandapower/CAPABILITIES için **30.000 ms** ayrı aşama sınırı ve hata kodu kullanır. Hesap yanıtının **300.000 ms** sınırı ayrı kalır.

Önceden kurulu manifestin UTF-8 BOM içerdiği ayrıca görüldü. Chrome bu manifesti yerel testte kabul etti; dolayısıyla gözlenen 3 saniyelik yanlış zaman aşımının kanıtlanmış nedeni BOM değildir. Güncel kurulum scripti BOM'suz UTF-8 yazar. Chrome'un genel `lastError` mesajı registry eksikliği, manifest yolu ve Python ortamı hatalarını her durumda tek tek ayıramaz; `tools/native-host-smoke.mjs` bu zinciri yerelde ayrı doğrular. Eski manifest geri yüklendikten sonraki `--allow-bom` koşusunda framed stdout temizdi, stderr boştu, CAPABILITIES **5.106 ms** içinde geldi.
